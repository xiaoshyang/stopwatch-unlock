# 需求整理：macOS 一键解锁（外置指纹方案的替代实现）

## 1. 一句话需求

在 macOS 锁屏/登录界面上，通过一次物理触发（按键 / 触摸 / 指纹模块均可），自动"输入登录密码并回车"，实现一键解锁。终极目标是接上指纹模块，复刻网上视频里"外置指纹解锁"的效果；现阶段先用 ESP32 上的按键/触摸代替指纹来触发。

## 2. 原理与关键结论（为什么必须用硬件）

视频方案的原理：那个"外置指纹识别器"本质上是一个 USB HID 键盘（指纹芯片 + 单片机模拟键盘）。指纹匹配成功后，单片机向 Mac"逐字打出"密码 + 回车。在 macOS 看来，它就是一把普通的键盘。

关键系统限制（这决定了技术路线）：

- macOS 锁屏界面（loginwindow / SecurityAgent）运行在独立的安全上下文中：
  - 用户态软件**无法向密码框注入按键**：AppleScript、辅助功能（Accessibility）、CGEvent 合成事件全部无效；
  - 后台常驻程序在锁屏界面**也收不到键盘按键**，所以"在 Mac 上装一个软件，监听某个键然后自动输入密码"这条路走不通；
  - 常规软件路线中唯一能在锁屏注入输入的是驱动级虚拟键盘（如 Karabiner-Elements 的 DriverKit 虚拟设备），但开发复杂度远超一块 ESP32，不推荐。
- 系统在锁屏界面只接受"真实硬件输入"——即 USB / 蓝牙 HID 键盘级别的事件。

结论：

1. 你判断"用什么触发不重要"是对的，但触发器本身必须**能作为键盘向 Mac 发 HID 事件**（或驱动一个能发 HID 事件的东西）。
2. 方案 (a)「用 Mac 键盘上的某个键触发 Mac 端软件自动输入」**不可行**，原因如上。切输入法的键、Caps Lock、任何键都一样。
3. ESP32 正好能干这件事：把密码存在 ESP32 里，物理触发时它以键盘身份把密码"打"进锁屏界面。对 Mac 零软件安装、零配置。

## 3. 触发方案对比

| 方案 | 可行性 | 说明 |
|---|---|---|
| (a) Mac 键盘某键 → Mac 端软件自动输入 | ❌ 不可行 | 锁屏界面屏蔽软件合成输入，软件也监听不到该界面的按键 |
| (b) ESP32 经典款（WROOM-32）→ 蓝牙 BLE 键盘 | ✅ 可行 | 与 Mac 配对一次后，锁屏界面接受蓝牙键盘；板上按键/触摸脚触发；唤醒后重连有 1~2 秒延迟 |
| (c) ESP32-S2 / S3 → USB HID 键盘 | ✅ 最推荐 | 原生 USB，插线即用，与视频方案同构；即时响应；S3 还自带蓝牙 |
| (d) ESP32 + 指纹模块（AS608/R307/FPM10A，约 30~60 元） | ✅ 终极形态 | 指纹匹配成功才输出密码，安全性才真正成立 |
| (e) 其他现成硬件：Arduino Leonardo / Pro Micro、树莓派 Pico、Digispark、成品宏键盘 | ✅ 同理可行 | 都是 USB HID 键盘方案 |

> **硬件决策（已确认）**：手上的设备是 M5Stack StopWatch（SKU C152），主控 ESP32-S3R8（16MB Flash / 8MB PSRAM），带原生 USB → 走 **路线 (c)：USB HID 键盘**。触发用板上黄色按键 KEYA（GPIO1），蓝色 KEYB（GPIO2）预留。无需购买任何硬件。
> 固件见 `firmware/stopwatch_unlock/`，烧录说明见 `firmware/README.md`。
> StopWatch 补充：进入下载模式 = 长按电源键约 2 秒（绿灯亮）；板载 1.75" 圆形 AMOLED 触摸屏（466×466）和振动马达，留作后续版本的状态反馈/触摸触发。

## 4. 功能需求

- **FR1 触发**：一次物理触发 = 一次完整解锁动作。触发源支持：板上 BOOT 键 / 触摸引脚（贴一块铜箔）/（后续）指纹模块。
- **FR2 输入序列**：先发一个任意键唤醒屏幕 → 延时（默认 500ms，可调）→ 逐字输入密码 → 回车。
- **FR3 密码存储**：通过串口（或蓝牙）配置写入 NVS，不硬编码在源码里；至少提供简单混淆，并明确告知存储的可提取性（见第 6 节）。
- **FR4 防抖与互锁**：触发后 2 秒内忽略重复触发。
- **FR5 指纹模式（可选，终极需求）**：AS608 录入指纹；只有匹配成功才输出密码；连续失败 5 次锁死，需连接电脑重新授权。
- **FR6 状态反馈**：板载 LED——待机慢闪 / 解锁动作完成常亮 2 秒 / 指纹错误快闪。
- **FR7 免驱**：对 Mac 不安装任何软件。

## 5. 非功能需求

- 从触发到回车完成 ≤ 1.5 秒。
- 供电：USB 线常供电。注意部分 Mac 睡眠时会断开 USB 供电/蓝牙，唤醒瞬间设备需要重新枚举/重连（USB 几乎即时，BLE 需 1~2 秒）——这是优先 USB 路线的主要原因。
- 多用户登录界面：默认按"单用户、密码框已聚焦"处理；如多用户，可配置先按 ↓ 选择用户或输入用户名 + Tab。
- FileVault：若开启，冷开机时先出现 EFI 预引导密码界面，USB 键盘在该界面同样有效；但设备无法区分当前在哪个界面，冷开机场景手动触发两次即可。

## 6. 安全边界（必须清楚）

1. 密码存储在设备 flash 中，可被提取——拿到设备 ≈ 拿到密码。
2. 纯按键/触摸触发 = 任何碰到设备的人都能解锁你的 Mac，安全性等同把密码贴在屏幕上。因此：**只有演进到指纹方案（FR5），这个项目在安全上才有意义**；按键方案只作为开发中间步骤。
3. 建议缓解：指纹触发 + 失败锁死 + 指纹录入只留自己手指 + 设备放在顺手但不高调的位置。
4. 若接受风险仅在家用，按键版可直接使用。

## 7. 验收标准

1. 锁屏状态（合盖再开盖，或 Ctrl+Cmd+Q）下触发一次，Mac 在 1.5 秒内解锁进入桌面。
2. 睡眠唤醒后同样可用（含 USB 重新枚举 / BLE 重连时间）。
3. （指纹版）他人指纹触发不输出密码；连续 5 次失败锁死。
